# Testing and publishing a form

Test while the survey is unpublished, using your editor preview. Submitting that preview creates a response when the standard storage handler is used; there is no separate automatic test-results area.

1. Save and click **View**. Start the form and read the introduction.
2. Leave required fields empty and try an invalid email or number. Check that the form explains what to correct.
3. Complete a valid response using clearly labelled test details. Test each choice, page jump, and language the form supports.
4. Check the thank-you page and any confirmation emails.
5. Open **Results → Results editor** and confirm that the answers were stored as expected.
6. Check keyboard navigation and a narrow screen. Test saved progress or repeat submissions if enabled.
7. Remove clearly identified practice responses using the results controls only when you no longer need them. Read the deletion confirmation; do not assume responses have a trash or undo function.
8. Check the form's publication period and access settings, publish it, then test its address as the intended audience. Use a private window for public forms or a suitable test account for restricted forms.

Check that **Deactivated** is off and a submission limit has not already been reached. An editor's successful preview does not prove anonymous visitors can respond.

Finally, add a link or menu entry wherever people should find the form. Publishing alone does not put it in navigation. Agree who will check new responses and when they will follow up.
